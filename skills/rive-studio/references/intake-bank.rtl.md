## 1. כללים לכל השאלות

- האפשרות המומלצת תמיד ראשונה, עם "(מומלץ)" בסוף התווית. ההמלצה נגזרת מהראיות, לא מהרגל.
- בלי אפשרות "אחר" או "דלג": הכלי מוסיף "Other" לבד.
- תיאור כל אפשרות אומר מה הבחירה משנה בתוצאה, לא רק מה היא אומרת.
- בלי קו מפריד ארוך, בלי קו בינוני ובלי מקף עברי באף שדה. רק "-".
- ב-multiSelect אין פסיקים בתוויות (התשובות מחוברות בפסיק).
- תצוגה מקדימה: עד 40 עמודות ו-18 שורות, ASCII בלבד בתוך מסגרת, בלי עברית בין קווי מסגרת. תצוגות רק לבחירות ויזואליות או מבניות.
- כל payload נשמר כקובץ JSON ועובר `node ${CLAUDE_SKILL_DIR}/scripts/lint-ask.mjs <file>` לפני הקריאה.
- לא שואלים שאלה שהתשובה עליה לא משנה את הבנייה. אם הראיות עונות, מחליטים ורושמים בתקציר תחת "Inferred".

## 3. סבב 0: מחקר שקט (בלי שאלות)

לפני השאלה הראשונה אוספים, ורושמים כראיות:
- **פלטפורמה וסטאק** מהקבצים: `package.json` (next, astro, react, react-native), `build.gradle.kts` עם Compose, `pubspec.yaml`, `Package.swift` או `Podfile`.
- **טוקנים ומותג**: הגדרות Tailwind, משתני CSS, קבצי theme, פונטים, `dir` ו-`lang`, לוגו SVG, איורים וצילומים קיימים.
- **מסמכי עיצוב**: `design/BRIEF.md` ו-`design/CONCEPT.md` (מ-pattern-breaker), `DESIGN.md`, `PRODUCT.md`, חוזה Rive קיים.
- **מסמכי הכיוון של site-director**, אם קיימים: `design/world-dossier.rtl.md` (תיק העולם), `design/design-decisions.rtl.md` (יומן ההחלטות, או `DECISIONS.md` / `DECISIONS.rtl.md` בשורש כשהיומן נמצא שם) ו-`design/storyboard.rtl.md` (הסטוריבורד). מוצאים את השורה של היצירה בסטוריבורד ואת פריטי התיק שהיא מצטטת. מה שהם סוגרים לא נשאל: הטבלה ב-`intake.md` §9. כל תשובה כזו נרשמת תחת Inferred עם הקובץ והשורה כמקור.
- **קבצי `.riv` קיימים** בריפו: מריצים עליהם את ה-probe ורושמים את המבנה.
- **כלי Rive**: האם כלי ה-Rive MCP זמינים בסשן הזה, והאם `rive doctor` עובד (ה-CLI מותקן). זה קובע את ההמלצה בשאלת "דרך עבודה".
- **האתר החי**, אם יש: צילום של המקום שבו היצירה תשב, בדסקטופ ובמובייל.

מכאן נגזרות האפשרויות של "תפקיד", "סגנון" ו"להימנע", והמלצות "אופי תנועה" ו"עוצמה".

## 4. סבב 1: מה, איפה ואיך

### תפקיד
- header: `תפקיד` · multiSelect: false
- שאלה: מה התפקיד של Rive בפרויקט הזה?
- אפשרויות (מסדרים לפי הראיות, המומלצת ראשונה):
  - **רגע חתימה**: סצנה אינטראקטיבית אחת במקום הכי חשוב, ב-Hero או ברגע בגלילה. כל התקציב הולך לרגע אחד שזוכרים.
  - **מיקרו-אינטראקציות**: סט כפתורים, טוגלים, אייקונים ומשוב בשדות, עם אופי תנועה אחד לכל המוצר.
  - **דמות שמגיבה**: דמות שנבנית מהצורות של המותג ומגיבה לאירועים אמיתיים במוצר. מוסיפה לחוזה סט הבעות ומצב רוח.
  - **מצבי מערכת**: טעינה, הצלחה, שגיאה ומסך ריק כחוויה אחת עקבית, במקום ספינרים גנריים.
- ב-Other נכנסים: ווידג'ט נתונים (מד, התקדמות), אונבורדינג, מסך פתיחה, ממשק משחק.

### פלטפורמה (רק אם לא ברור מהקבצים)
- header: `פלטפורמה` · multiSelect: true
- שאלה: איפה זה ירוץ?
- אפשרויות: הפלטפורמות שזוהו בקבצים קודם, ומשלימים עד 4 מתוך:
  - **Next.js או React**: רכיב client שנטען בעצלות, data binding דרך hooks.
  - **Astro או HTML**: custom element קל שעובד בכל דף ונטען רק כשהוא נראה.
  - **Android Compose**: רכיב Compose עם data binding מקוטלין.
  - **iOS SwiftUI**: RiveViewModel בתוך SwiftUI.
  - **Flutter**: ווידג'ט Rive עם controller.
  - **React Native**: רכיב RN עם data binding.

### דרך עבודה
- header: `דרך עבודה` · multiSelect: false
- שאלה: איך קובץ ה-Rive ייבנה?
- ההמלצה: **Claude בונה בקוד**, חוץ מדמות או איור שצריכים עצמות ו-mesh כשה-Editor MCP מחובר, ואז **Claude בונה ב-Editor**. אם הכלי הנבחר לא מותקן, ההתקנה ב-`build-cli.md` §2 או ב-`build-mcp.md` §1 רצה קודם, באישורך.
- אפשרויות:
  - **Claude בונה בקוד**: כותב את הקובץ כטקסט (RML) עם ה-Rive CLI. אתה רואה חלון תצוגה חי שמתעדכן בכל שמירה, וכל מצב נבדק בצילום אוטומטי לפני שאתה רואה אותו. אפשר להמשיך ללטש ב-Editor אחר כך.
  - **Claude בונה ב-Editor**: עורך ישירות את הקובץ הפתוח ב-Rive Editor דרך MCP, ואתה רואה כל שינוי על המסך. הכי טוב לאיור, דמויות ועבודה משותפת. דורש את אפליקציית Rive פתוחה.
  - **דף בנייה מדויק**: אני כותב דף בנייה (שמות, זמנים, עקומות, שכבות) ומכין את הצורות כ-SVG. אתה או מעצב בונים ב-Editor לפי הדף.
  - **קובץ קיים**: כבר יש `.riv` ממעצב או מהקהילה של Rive. אני בודק את המבנה שלו, כותב חוזה לפיו ובונה סביבו את הקוד. בקובץ קהילה בודקים רישיון ומחליפים כל מה שגנרי.

### טריגרים
- header: `טריגרים` · multiSelect: true
- שאלה: מה מניע את האנימציה?
- אפשרויות:
  - **ריחוף ולחיצה**: מצבי hover, press ו-focus. בטלפון כל תגובת ריחוף מקבלת גרסת נגיעה.

### עוצמה
- header: `עוצמה` · multiSelect: false (עם תצוגות מקדימות)
- שאלה: כמה מקום Rive תופס בחוויה?
- העוצמה קובעת גם את תקציב הקובץ, אז אין שאלת תקציב נפרדת.

**מאוזן (מומלץ)**: משוב בכל הרכיבים ורגע חתימה אחד. ההמלצה הנכונה לרוב המקרים; כשהראיות מצביעות אחרת, אפשרות אחרת עולה לראש עם "(מומלץ)".
```
INTENSITY  balanced
feedback   all controls
signature  1 moment
character  optional, reacts only
idle       still, rare cues
riv files  1-2, <= 150 KB total
perf risk  low
```

**עדין**: רק משוב ברכיבים המרכזיים, בלי רגע חתימה. הכי בטוח לביצועים.
```
INTENSITY  subtle
feedback   key controls only
signature  none
idle       still
riv files  1, <= 60 KB
perf risk  lowest
```

**מופע**: הסצנה או הדמות הם החוויה עצמה. דורש בדיקות ביצועים במובייל ותמונת poster.
```
INTENSITY  showpiece
feedback   all controls
signature  the scene is the page
character  full expression set
idle       alive, then settles
riv files  1-3, <= 600 KB + assets
perf risk  medium-high
needs      mobile perf test, poster
```

## 6. בין סבב 2 ל-3: מעבדת תנועה

מריצים את `motion-sketches.md`: סקיצות A, B ו-C (או A ו-B במשימה קטנה), כל אחת תחת אילוץ אחר, לפי רשימת המצבים שבתקציר. `scripts/sketch-board.mjs` מאחד אותן ללוח אחד (`board.html`) עם מעבר בין מצבים, האטה, תנועה מופחתת וכיוון. פותחים את הלוח בחלונית הדפדפן, עוברים על כל מצב, ורק אחרי שנתי ראה אותו שואלים את סבב 3.

באתר ש-site-director מנהל, שורת הסטוריבורד ופריטי התיק שהיא מצטטת הם החומר של כל הסקיצות. הקונספט כבר נבחר ברמת האתר, אז אין מעבדת קונספט שנייה: הסקיצות שונות זו מזו בתנועת היד ובתזמון, לא ברעיון.

### מצבים (רק אם לא נגזר מהתפקיד)
- header: `מצבים` · multiSelect: true
- שאלה: אילו מצבים חייבים להיות מעוצבים?
- אפשרויות: ארבעת המצבים הרלוונטיים לתפקיד מתוך הטבלה ב-`motion-craft.md` §3, למשל **ריחוף ולחיצה** · **טעינה והצלחה** · **שגיאה** · **מושבת**. מצב idle ופוקוס מקלדת תמיד מעוצבים ברכיב אינטראקטיבי ולא נשאלים: טבעת הפוקוס של רכיב ה-DOM נשארת, ו-`isFocused` ב-Rive יכול להוסיף עליה.

### תנועה מופחתת
