# דף בנייה: <piece>

דף עבודה לבנייה ידנית ב-Rive Editor, כשאין CLI ואין חיבור MCP. כל שם כאן מדויק ותואם את `CONTRACT.md`: אותיות גדולות וקטנות, בלי רווחים ובלי עברית בשמות. עובדים לפי הסדר; כל שלב נגמר בבדיקה קצרה.

**קלט:** `CONTRACT.md` (שמות, טיפוסים וכיוונים), טבלת התזמונים מהסקיצה שאושרה, קבצי ה-SVG ב-`design/rive/<piece>/svg/`.
**פלט:** `<piece>.riv` מיוצא לנתיב שבחוזה.

---

## 1. קובץ וארטבורד
- קובץ חדש בשם `<piece>`.
- ארטבורד `<Artboard>` בגודל `<w> x <h>`. <Layout: כן או לא, ואם כן אילו כללי פריסה>.
- מסמנים את הארטבורד כ-Component (Shift+N), או מגדירים אותו כארטבורד ברירת המחדל. ארטבורד שאינו Component הוא טיוטה ולא ייוצא.
- רקע שקוף, אלא אם החוזה אומר אחרת.
- **בדיקה:** שם הארטבורד זהה לחוזה, והוא מסומן כ-Component.

## 2. ייבוא ומבנה
- גוררים את `<file>.svg` לארטבורד.
- מבנה ושמות (שמות קבוצות באנגלית, camelCase):

| קבוצה | מכילה | הערות |
|---|---|---|
| `<body>` | <צורות> | נקודת ציר במרכז התחתון |
| `<mirror>` | <חלקים עם כיוון> | זה מה שמתהפך כש-`isRtl` דולק |

- **בדיקה:** אין צורות כפולות מהייבוא, נקודות הציר במקום.

## 3. View Model ו-Enums
- יוצרים Enum `<Enum>` עם הערכים: <values>.
- יוצרים View Model `<ViewModel>` עם המאפיינים מהחוזה, באותו סדר:

| מאפיין | טיפוס | כיוון | ברירת מחדל |
|---|---|---|---|
| `<isHovered>` | boolean | מהאפליקציה ל-Rive | false |
| `isRtl` | boolean | מהאפליקציה ל-Rive | false |
| `prefersReducedMotion` | boolean | מהאפליקציה ל-Rive | false |
| `<ctaPressed>` | trigger | מ-Rive לאפליקציה | |

- משייכים את ה-View Model לארטבורד ויוצרים instance ברירת מחדל.
- **בדיקה:** כל מאפיין מהחוזה קיים, עם אותו טיפוס.

## 4. אנימציות (טיימליינים)
אנימציה אחת לכל פעולה. זמנים במילישניות, עקומות כ-cubic-bezier מהסקיצה.

| אנימציה | זמן | מה זז | ערך התחלה | ערך סוף | עקומה |
|---|---|---|---|---|---|
| `<hoverIn>` | 0-150 | `<body>` y | 0 | -2 | 0.2, 0, 0, 1 |

- כל keyframe מתחיל ב-Linear: מעבירים כל מפתח ל-Cubic עם העקומה מהטבלה (או Hold כשצריך קפיצה).
- לולאות: מסמנים Loop רק לאנימציות שהחוזה מגדיר כלולאה.
- **בדיקה:** לא נשאר אף מפתח ב-Linear, וכל אנימציה מנוגנת במהירות 0.25 ומושווית לסקיצה.

## 5. State Machine
- State Machine בשם `Main`.
- שכבות (ערוץ עצמאי לכל שכבה):

| שכבה | מצבים | מעברים (תנאי, משך) |
|---|---|---|
| `<main>` | idle, hover, pressed | idle אל hover כש-`isHovered` true, 150ms |

- כל מעבר מוגדר עם "allow exit during transition", כך שאפשר לקטוע אותו באמצע בלי קפיצה.
- `isRtl` true: התנועות עם כיוון מתהפכות (הקבוצה `<mirror>`, או Layout בכיוון RTL).
- `prefersReducedMotion` true: מעברים מיידיים, תמונות סופיות ואין לולאות.
- **בדיקה:** בחלונית ה-State Machine משנים כל מאפיין ידנית ובודקים כל מעבר, כולל קטיעה באמצע, RTL ותנועה מופחתת.

## 6. Listeners ואותות לאפליקציה
- Listeners רק אם החוזה דורש קליטה בתוך הקובץ. בדרך כלל הקוד קובע את המאפיינים.
- אות מ-Rive לאפליקציה: trigger מהחוזה (`<ctaPressed>`) שה-Listener מפעיל. Rive Event רק ל-open-url, לאודיו או לקובץ ישן.
- **בדיקה:** ה-trigger משתנה בחלונית ה-View Model בזמן הרצה.

## 7. ייצוא
- מייצאים `.riv` לנתיב `<runtime path>`.
- גודל הקובץ לא עולה על `<maxKB>` KB. אם עולה: מקטינים תמונות מוטמעות, מסירים פונטים מיותרים, מוחקים אנימציות לא בשימוש.
- בתוכנית Free הקובץ המיוצא מציג מסך פתיחה של Rive: ללקוח מייצאים מסביבת Cadet ומעלה.
- מריצים את ה-probe: `node <skill>/scripts/rive-probe.mjs <file> --contract design/rive/<piece>/CONTRACT.md --shots design/rive/<piece>/shots`
- **בדיקה:** ה-probe מסתיים בלי הבדלים מהחוזה, ובצילומים אין מסך פתיחה או סימן מים.
